## Known gaps and limitations

1. **No live model anywhere.** Generation quality, real TTFT/ITL/tok/s, judge scores, LLM-level injection resistance and whether the LLM follows the memory and summary rules are all unmeasured. The ollama abstention threshold (0.24) is uncalibrated.
2. **The baseline answers are weak.** Answers are padded with neighbouring sentences (6 of 16 audited). Short standalone questions can be treated as follow-ups. On `lear-076` the baseline gives an off-topic answer rather than a refusal.
3. **Retrieval.** Context precision is low (about .25–.29). The reranker is heuristic, not a cross-encoder.
4. **Documentation.** The narrative pages cover 43 of 79 Lear modules. The 57 heuristic credential keys in `reference/configuration_env.md` may include false positives, such as token-count settings. The environment-variable grouping is by name prefix.
5. **Lear itself (reported, not fixed).**
   - `GET`/`POST /api/incident/{incident_id}/approve` has no authentication and leads to `kubectl` actions.
   - The Slack interactivity endpoint has no signature check.
   - The pinned commit's CI failed, and the Lear suite has 28 failures (12 with `LEAR_MOCK_SERVICES=false`).
6. **Core rag-formation gaps (reported; the core is unchanged without approval).**
   - The legacy `RAGEngine.ask` has no embedding-fingerprint check.
   - The legacy ingest keeps stale chunks after a chunking change.
   - The core engine falls back to extractive generation silently. The Lear layer guards all three.
7. **`.env.example` (core section).** `RAG_RATE_LIMIT_PER_MINUTE`, `RAG_MAX_CONCURRENT_QUERIES` and `RAG_DEFAULT_TENANT` are commented out. `RAG_SPACY_MODEL` and `RAG_DISTRIBUTIONAL_*` are not listed. Every `RAG_LEAR_*` variable is listed.
8. **Divergence.** The remote branch `arena/5f16d127-rag-formation` (`9e0918b58b48`, a core qualification) is unmerged and was not merged here. Two Lear fork branches are unmerged.
9. **Process.** Rate limits are per process. The user id is an isolation label, not an authenticated identity.

## Run commands

See [README.md](README.md). On this machine the working path is `--backend baseline`. With Ollama, the same commands without that flag are the qualifying path:

```bash
python3 -m ragformation lear doctor
python3 -m ragformation lear docs verify --source /path/to/Lear-backend-Avi
python3 -m ragformation lear index rebuild && python3 -m ragformation lear index stats
python3 -m ragformation lear ask "<question>"
python3 -m ragformation lear eval run --suite all --judge on
python3 -m ragformation lear bench --users 1,2,5
python3 -m ragformation lear report --source /path/to/Lear-backend-Avi
```

**To reach GO:**
1. Install Ollama on a machine whose downloads are allowed.
2. Pull the three models (about 2.5–3 GB).
3. `lear doctor` must exit 0 with exact parameter counts.
4. `lear index rebuild --full`.
5. Run calibration+dev, calibrate the ollama threshold on calibration only, then run one qualifying test evaluation with the judge.
6. Run `lear bench --users 1,2,5`.

The holdout has already been used once. A qualifying holdout result therefore needs a fresh holdout, added transparently as golden v2 cases.
